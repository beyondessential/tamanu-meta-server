Application and machine detail pages

One page each, with the checks that belong to that grain, backlinks between them, and the group's other pages at the foot of both. The application page is where an operator lands; the machine page is a hop up from it.

What is new here

Everything drawn below is the server detail page as it stands: the same outlined header chips, the icon-only action buttons that reveal their label on hover, the filled health chip, the caption-over-value info fields, the bordered check rows with their result icons and detail lists, the five-then-expand cap. This is not a restyle.

New A second page for the machine. The subject tag on machine checks in the application's list. The group tree at the foot, replacing the flat sibling list. The link up to the machine.
Removed The status dot strip beside the title.
Moved Backups and identity to the machine. Everything else stays where it is, on whichever page now owns it.

What sits where

Application only url and the certificates that follow it, its own notes and tags, its billing labels, and the mobile listing.
Machine only The identity, backups, the machine's own notes and tags, hardware and OS figures, and the reachability threshold.
Both, separately Notes and tags, since each grain has its own. The group and its siblings, listed from each grain's point of view.
Amalgamated The application's checks are presented together with its machine's, in one list, each marked with its subject. Names read bare here, since the page is one application; the catalog and the fleet views carry the type-qualified name.
Gone from both The status dot beside the title. The health chip answers the same question in words, and the group tree at the foot says how everything around it is.

Nothing here asks the operator what is on the box. They named it, put it in a group, and ran one command. Everything else arrives.

The empty state is not an error and does not read as one. A machine with no applications is the normal condition of a machine that was created a minute ago, and it resolves itself.

The amalgamated list is what stops the split costing anything. An operator triaging an application sees every check bearing on it, its own and its box's, in the order of urgency they always did. The machine tag says where a check came from without making it somewhere else to look.

The machine page shows the same checks unamalgamated, because from the box's point of view its applications' checks are not its business. It is the page for "is this host healthy", not "is this deployment healthy".

Reachability appears on both, as one filing seen from two places. Silencing it from either is the same machine-scoped silence.

Every page ends with the group's whole tree: rank, then machine, then the applications on it. It is the same shape the group page shows, so an operator learns one arrangement and reads it everywhere, and moving sideways never goes back through the group. The current page is marked in place rather than omitted, so the tree reads as a map rather than a list of everything else.

The application page adds one link upward to its machine, which is the only hop the hierarchy needs.

A machine sits under the rank of its highest-ranked application, on the same rule its billing stage uses. A box shared by a production and a test workload files under production with its test application nested inside it, which is worth seeing rather than hiding: the box is production-grade because something production is on it.
