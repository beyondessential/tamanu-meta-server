Machine navigation

Two questions, shown together because they answer each other: whether the detail view is machine-first like the edit form, and whether the fleet gains a machine list. Rows, chips, and dots are the existing components.

Detail view

Nauru Central and Nauru Facility share one machine. Everything outside the machine material is the server detail page as it stands.

Group listing

The group page lists its servers grouped by rank. With machines, either the rows stay flat and name their machine, or shared machines enclose their applications.

One new chip, no new structure. Rank grouping is untouched, and the machine reads as another classification alongside product and kind.

Risk: sharing is only visible by noticing two chips match, which is exactly the noticing the split exists to remove. Costs a chip on every row to describe a property most rows do not share.

Sharing is structural, and absent otherwise. A lone application is the row it is today; only a shared machine gains a wrapper, so the listing stays flat almost everywhere.

Matches the status page's grouping and the edit form's shape. Risk: two row depths in one list, and the machine header competes with the rank overline directly above it.

Machine list

Servers has tabs for Groups, Ungrouped, Archived, Figures. A Machines tab would sit among them and answer "what is on this box", which no current view does.

Machine Applications Platform Group bestool
nauru-prod-01 Nauru Central, Nauru Facility Ubuntu 22.04 Nauru 0.41.2
nauru-test-01 Nauru Test Ubuntu 22.04 Nauru 0.41.2
fiji-prod-02 Fiji Facility Ubuntu 20.04 Fiji 0.39.8

Earns its place only if machines are worth listing on their own. It is where a fleet-wide "which boxes are on old bestool" or "which are shared" gets answered, and the natural landing place if the detail view goes machine-first. If the detail view stays application-first, this tab is a second index of the same fleet.
