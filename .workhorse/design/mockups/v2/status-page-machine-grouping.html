Status page: banded group cards

Group cards become narrower and taller, split into three bands: name and version, the dots, then incident and operator marks. Ranks become rows separated by a light rule, replacing the triangle. Every machine is enclosed, whether it carries one application or several.

Filled segments divided by a vertical rule, squaring off the bottom of the card. Operators on the left, incident right-aligned in the space left over. Omitted when there is neither, so a quiet card is two bands.

Two dots in one pill is the whole point. Nauru's production central and facility share a box, and it has gone down: one pill, both red, one incident. The test facility on its own machine is untouched below the rule.

What it replaces

The same group today: one flat strip, a hollow triangle at the rank break, and nothing saying that the first two dots are one box.

Machine state on the enclosure

The pill is the machine, so it can carry the machine's own state while the dots carry each application's. That separates two cases which read identically today.

Machine fine

Box healthy, both applications healthy.

App sick

Box healthy, one application failing. The pill stays neutral.

Machine degraded

Disk filling up. Both applications warn because the machine's checks count on each, and the pill says why.

Machine down

Box gone, so everything on it is unreachable.

It answers "is it the box or the app". Two red dots in a neutral pill means two applications happened to fail; two red dots in a red pill means one box took them both. Today those are the same picture.

The machine-degraded case shows the reinforcement rather than redundancy: every dot warns because a machine check counts toward every application on it, and the pill is what says the cause is shared rather than coincidental.

Rank labelling

The initials are dropped: production, clone, demo, test, dev gives P, C, D, T, D, and demo against dev has no fix that still reads as an initial. Two remain, both spelling the rank out. Rows are filled here so the overlap is visible: the production row holds six machines and wraps.

The hover label costs nothing until asked for. A fleet of quiet cards stays quiet, and the label appears only where an operator is already looking. The watermark is readable without interaction but is permanent noise on every card, on a page whose job is to be scanned rather than read.

Both overlap dots on a full row, which is unavoidable at this card width. The difference is that the watermark overlaps constantly and sits behind, while the hover label overlaps only while hovered and sits on top, so it is legible when it matters and absent when it does not.

Hovering the card reveals every row's label at once rather than one per row, so a single hover gives the whole breakdown. Say if it should be per-row instead.

Still worth weighing against doing nothing: rows are already ordered highest rank first, which is all the triangle conveyed, and dot tooltips already name the rank.

The enclosure carries no meaning alone, only its contents. Because every machine is enclosed, an operator never has to notice whether a pill is present, only how many dots are inside it. That is what makes the shared case readable without making the common case noisy.

Rows also give the rank break more room than a triangle in a wrapping strip did: a group whose members wrapped mid-rank previously put the separator anywhere on the line, while a row break cannot land in the wrong place.
